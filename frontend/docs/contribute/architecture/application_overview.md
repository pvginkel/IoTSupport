# Application Overview

The IoT Support frontend is a React 19 + TypeScript single-page app over the IoT Support backend's REST API and its SSE stream. It manages device models and devices — a device's configuration, logs and core dumps — shows the rotation dashboard, and runs Flash device and Provision device over USB from the browser. This overview orients contributors to the architecture and highlights the pieces most relevant when extending tests or features.

## High-Level Stack

- **Framework**: React 19 with function components and hooks
- **Routing**: TanStack Router with file-based route modules in `src/routes/`; `pnpm generate:routes` (`tsr generate`) writes `src/routeTree.gen.ts`, which is not committed
- **Data Fetching**: TanStack Query (`@tanstack/react-query`) through generated OpenAPI hooks over an `openapi-fetch` client
- **Styling**: Tailwind CSS 4 with Radix UI primitives; shared components in `src/components/primitives/` and `src/components/ui/`, class maps and the theme in `src/styles/`
- **Editors**: Monaco (`@monaco-editor/react`) for device configuration, model schemas and core-dump output
- **USB**: `esptool-js` over Web Serial, wrapped by `src/lib/esptool/`
- **Build Tool**: Vite, serving on port 3100 and proxying `/api` — the SSE stream at `/api/sse` included — to `BACKEND_URL` (default `http://localhost:3101`)
- **Testing Mode**: Custom instrumentation under `src/lib/test/*`

## Routes

The sidebar (`src/components/layout/sidebar-nav.ts`) links **Device Models**, **Devices** and **Rotation Dashboard**.

- `routes/__root.tsx` – renders the provider tree and the app shell around the matched route.
- `routes/index.tsx` – redirects `/` to `/devices`.
- `routes/device-models/` – `index.tsx` (list), `new.tsx` and `$modelId.tsx`, both rendering `DeviceModelEditor`.
- `routes/devices/` – `index.tsx` (list), `new.tsx` (`DeviceEditor`), and the device's own routes:
  - `$deviceId.tsx` – the layout: loads the device and renders `DeviceDetailHeader`, whose `RoutedTabs` bar links the tabs, above the tab's route. The duplicate route renders without header and tabs.
  - `$deviceId/index.tsx` – redirects to the tab last used, kept in local storage, or to `edit`.
  - `$deviceId/edit.tsx` – the Configuration tab (`DeviceConfigurationTab`), which opens Flash device and Provision device.
  - `$deviceId/logs.tsx` – the Logs tab (`DeviceLogsTab`).
  - `$deviceId/coredumps.tsx` with `coredumps/index.tsx` and `coredumps/$coredumpId.tsx` – the Core dumps tab (`CoredumpAccordionTable`), the latter with one dump expanded.
  - `$deviceId/duplicate.tsx` – a new device prefilled from this one (`DeviceEditor`).
- `routes/rotation.tsx` – the rotation dashboard (`RotationDashboard`).

## Generated API Client

- `pnpm generate:api` fetches the running backend's OpenAPI spec (`/api/docs/openapi.json`, port `PORT` or 3101) into `openapi-cache/openapi.json` and generates the types, client and hooks under `src/lib/api/generated/`; `pnpm generate:api:build`, which `pnpm build` runs, generates them from the committed cache. `pnpm generate:api:with-backend` runs `../scripts/regenerate-openapi.py --frontend`, which starts a backend on a free port and runs `pnpm generate:api` against it.
- Custom hooks in `src/hooks/` (`use-devices.ts`, `use-device-models.ts`, `use-coredumps.ts`, `use-rotation.ts`, …) adapt API responses to frontend domain models (snake_case → camelCase) and invalidate queries after mutations.
- The generated hooks throw failures as `ApiError` (`src/lib/api/api-error.ts`, through `toApiError`). The generated client's middleware sends a 401 to the login page.

## Server State & Error Handling

- React Query handles caching and background refresh; `src/lib/query-client.ts` holds its defaults (no retry on 4xx, no mutation retries).
- Mutation errors surface through the toast system: the query client's default `onError` hands them to the toast function `QuerySetup` registers in `src/providers/core-providers.tsx`. In test mode every toast also emits a `toast` test event.
- Editors keep their state in the component (`DeviceModelEditor`) or in `useDeviceForm` (the device editor and Configuration tab) and report their lifecycle through `useFormInstrumentation`.

## Server-Sent Events

- One stream, `/api/sse/stream`, carries every event: the device logs, the rotation updates, the new-version notice and task events. `SseContextProvider` (`src/contexts/sse-context-provider.tsx`) holds it in the SharedWorker `src/workers/sse-worker.ts`, or over a direct `EventSource` in development, in test mode (unless the page loads with a `__sharedWorker` query parameter) and where SharedWorker is missing.
- Hooks subscribe with `useSseContext().addEventListener(event, handler)`: `useVersionSSE` (`version`), `useDeviceLogs` (`device-logs`), `useRotationDashboard` (`rotation-updated`) and `useSSETask` (`task_event`).

## Test Mode Architecture

- `src/lib/config/test-mode.ts` exposes `isTestMode()` and the `TEST_MODE` constant.
- When true, modules in `src/lib/test/` instrument forms, router transitions, React Query errors, toasts, global errors, list loading, UI state and provisioning, and the SSE provider forwards stream events.
- `src/lib/test/test-events.ts` defines the canonical payload types consumed by Playwright.
- Vite aliases `esptool-js` to `tests/support/mocks/esptool-mock.ts` in test mode, so Flash device and Provision device run against the suite's fake USB device.

## UI Composition

- Layout components (`src/components/layout/`) define the app shell, navigation, and responsive behavior, and the list, detail and form screen layouts.
- Domain components (`src/components/devices/`, `src/components/device-models/`, `src/components/rotation/`) encapsulate feature-specific UI such as editors, tables, tabs and modals.
- Shared UI building blocks live in `src/components/primitives/` (exported through its `index.ts`) and `src/components/ui/`.

## Key Contexts & Providers

- `App.tsx` wraps the router in `CorrelationProvider`. `routes/__root.tsx` renders `Providers` (`src/providers/index.tsx`), which nests three groups:
  - `CoreProviders` – `QueryClientProvider` > `ToastProvider` > `QuerySetup`
  - `AuthProviders` – `AuthProvider` > `AuthGate`, which holds the app until the user's session resolves
  - `SseProviders` – `SseContextProvider` > `SseGate` > `DeploymentProvider`, which drives the new-version notification bar
- `ToastProvider` (`src/contexts/toast-context-provider.tsx`) supplies toast operations; in test mode it wraps them to emit `toast` events.
- The query client (`src/lib/query-client.ts`) centralizes React Query configuration, including default error handling.

## Callouts for Test Authors

- Prefer adding instrumentation by reusing existing helpers (see [Test Instrumentation](./test_instrumentation.md)).
- Give new elements a `data-testid` in the `<feature>.<element>` form the screens use (`devices.flash-modal.close-button`); see [Selector Patterns](../testing/selector_patterns.md).
- Keep new hooks colocated within `src/hooks/` and ensure they return camelCase data for UI components.
